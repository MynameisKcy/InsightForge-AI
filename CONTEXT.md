# InsightForge AI

A multi-agent data-analysis platform: users ask questions in natural language, and a conversational agent either answers directly or runs a planned analysis pipeline that produces charts and a report.

## Language

**Smart Assistant (智能客服)**:
The conversational agent a user talks to. It answers directly or invokes tools — including the analysis pipeline — based on the query.
_Avoid_: "react mode", "React mode" (implementation name)

**Analysis Pipeline (分析流水线)**:
The SQL → Trend → Product → Risk → Visualization → Report → Export sequence that turns a natural-language analysis request into charts and a report. Invoked as a tool from the Smart Assistant — it is not a separate mode.
_Avoid_: "data analysis mode", "planner mode", "分析模式" (it is not a mode)

**Plan**:
An ordered list of Steps, generated by the LLM, describing how to fulfill an analysis request. Each Step declares which Specialized Agent runs and what it depends on.
_Avoid_: "workflow", "DAG"

**Step**:
A single unit of a Plan, dispatched to one Specialized Agent. Identified positionally (`step_N`) within the plan.
_Avoid_: "task" (reserved for the natural-language instruction a Step carries)

**Specialized Agent (子agent)**:
A stage of the Analysis Pipeline that does one job - SQL query, trend/product/risk analysis, visualization, report, or export. Each is a `BaseAgent` subclass orchestrated by the PlannerAgent via a typed `PipelineContext` (not the retired `prev_results` dict); it is not a tool the Smart Assistant calls directly. The trend/product/risk stages share a single `AnalysisAgent` class injected with an `AnalysisModule` adapter.
_Avoid_: "sub-agent tool", "tool" (tools are atomic reactive capabilities picked by the Smart Assistant; Specialized Agents are planned pipeline stages)

**Session**:
A conversation owned by one user, identified by `session_id`. The isolation boundary for Session Memory: one user's sessions do not share working context, and no user can read another's sessions.
_Avoid_: "conversation" (reserved for the raw turn sequence inside a Session)

**Session Memory (会话记忆)**:
The working context of a single Session - the recent turns and any compressed summary that form the LLM's context window for that session. Isolated per session and per user; rebuilt per request from that session's own history. Not the place for cross-session knowledge.
_Avoid_: "short-term memory" (time-based and fuzzy - short relative to what?), "会话内记忆"

**Long-Term Memory**:
User-scoped memory a Session can recall across sessions - the cross-session tier, deliberately separate from the session-scoped Session Memory. Built from the user's past-session summaries and retrieved by relevance to the current query; never shared across users.
_Avoid_: confusing it with a Session's own persisted summary (that is session-scoped, part of Session Memory)

**SQL Safety (查询通道安全)**:
The read-only enforcement guarding every query the SQL Agent runs through `DuckDBManager.execute`: an sqlglot-AST whitelist (SELECT / SHOW / DESCRIBE / SUMMARIZE only) plus a function blacklist (no file-read / network / write functions), rejecting multi-statement and DDL/DML. Lives in `database/safety.py`, alongside identifier quoting (`safe_ident`) and table-name / file-path validation. The management channel (the `_load_csv` / `load_csv_dataset` build-table paths) bypasses it by calling `conn.execute` directly — only the read-only query channel goes through SQL Safety.
_Avoid_: "SQL validator" (it is a read-only sandbox, not a linter); "the sandbox" alone (SQL Safety also covers identifier and path validation, not just the AST check).

**Chat Stream Protocol (聊天流线协议)**:
The SSE wire contract of `/api/chat`: preamble tokens (`[SESSION]`/`[TRACE]`/`[SESSIONS_RELOAD]`), progress-event routing (`[METRICS]`/`[DECISION]`/`[STEP]`), `[THINKING]` passthrough, sentence-paced body frames, disconnect sampling (mandatory at heartbeats + every 20 chunks), chart diff emission (`[CHART:url]`), and the cancellation contract (no `[DONE]`, no charts, no memory write). The vocabulary itself is owned once in `utils/sse_protocol.py` (token constants + `frame`/`parse_frame`), mirrored by the `SSE_PROTOCOL` literal in `api/static/js/app.js`; the lockstep is pinned by a contract test. Emission orchestration lives in `api/chat_stream.py`; the thread/heartbeat bridge in `api/sse.py`.
_Avoid_: "SSE 处理逻辑散在路由里" (retired — the route is thin); hand-written `'[TOKEN…]'` literals or magic `slice()` offsets outside the vocabulary owners (Python consumers use `frame`/`parse_frame`, JS uses `SSE_PROTOCOL`/`parseSSEFrame`).

**Report Markdown**:
The fixed Markdown dialect of the report stage: ATX headings (`#`..`###`), pipe tables with an optional `---` separator row, chart image references `![alt](ref)`, `- `/`N.` list items, whole-line `---` rules, and inline `**bold**`/`*italic*`/`` `code` `` marks. ReportAgent emits it; ExportAgent renders it to Word/PDF/HTML through the pure block parser `agents/markdown_blocks.py` — the single implementation of the dialect, with per-format inline-mark conversion left to each renderer.
_Avoid_: "通用 Markdown 解析" (it is a small fixed dialect, not a general-purpose parser); per-format walkers such as "docx/pdf/html 遍历器" (retired — parsing lives once in the block parser, formats are thin adapters over its Blocks).

**Reports Static Tree (reports 静态树)**:
The repo-relative `reports/` directory that `fastapi_server` mounts at the `/reports` web prefix — holding the `charts/` subtree (interactive HTML charts plus their kaleido-rasterized PNG siblings) and export outputs. Location conventions live once in `utils/report_paths.py`: directory/prefix constants and three named conversions — `fs_to_web_url` (any file in the tree), `chart_web_url` (charts-only, returns None for placeholders and non-chart files), `web_url_to_fs` (web prefix back to FS) — plus `png_sibling_path` (HTML→same-name PNG derivation).
_Avoid_: hand-rolled `"/reports/..."` regex/find logic at conversion call sites (serialization/report_agent/export_agent/charts are thin delegators); confusing the two web-URL semantics — "anything under /reports" (generic files) vs "charts only" (chart references).
